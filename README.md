云台和摄像头之间位置(无论角度还是位置)都是固定好了的

但是底座和云台之间就不一样了

云台旋转90度，底座保持不动，它们的相对角度就变化了，而如果用静态tf，它们的相对角度一直是写死了的
总之，摄像头和云台之间的相对位置和角度是一定不变的，锁死的，所以用静态tf可以解决问题
可云台和底座之间的相对位置和角度不是锁死的，得用动态

火控公式
先用直线距离除以弹速，估算初始飞行时间
用这个时间预测目标会移动到哪里（提前量）
计算子弹在飞行时间内会下落多少，把俯仰角往上抬补偿
用新的俯仰角重新算飞行时间，迭代几次让结果收敛
迭代次数一般 3-5 次就足够，再多也不会有明显提升
重力补偿是按竖直方向匀加速下落算的，足够步兵弹丸使用


所有节点的功能

视觉节点
识别 + PnP 解算 + TF 坐标转换 + 卡尔曼滤波，把目标在云台坐标系下的 3D 位置、速度，通过 /track_target 话题发给火控节点。
火控节点（当前代码）
接收目标数据 → 计算弹道补偿 + 运动提前量，解算出云台目标角度；同时监听 TF 获取云台当前真实姿态，判断是否对准目标、输出开火信号；最终把 [目标yaw, 目标pitch, 开火0/1] 打包为指令，通过 /gimbal_cmd 下发。
电控 / 云台
订阅 /gimbal_cmd，根据目标角度控制云台转动，收到开火信号后执行发射动作。
云台 TF 广播节点
接收电控发来的云台编码器数据，实时广播 base_link → gimbal_link 的坐标变换；火控节点通过监听该 TF，拿到云台实时角度，用于开火判定。

话题
/gimbal_encoder — 云台编码器角度
/track_target — 视觉跟踪目标信息
/gimbal_cmd — 云台控制指令 + 开火信号
相机图像话题 — 相机原始图像（名称自定义）
/tf — 动态坐标变换（底层）
/tf_static — 静态坐标变换（底层）


所以火控是这样的，先通过视觉节点的云台系目标结果拿来用预测公式算出预测目标角度

而后通过世界坐标系tf用自带的坐标变换得到真实的云台位姿

用预测和真实两者的位姿来比对，小于阈值就开火



x y z：相机相对云台的安装偏移（单位：米）
x：前后（云台向前为正）
y：左右（云台向左为正）
z：上下（云台向上为正）
roll pitch yaw：相机相对云台的安装姿态（单位：弧度）
roll：绕相机光轴的旋转
pitch：绕水平轴的俯仰
yaw：绕垂直轴的偏航
parent_frame：父坐标系（你的是 gimbal_link）
child_frame：子坐标系（你的是 camera_link）

0.02 -0.04 0.0 -1.5708 0.0 -1.5708 gimbal_link camera_link
表示相机安装在云台前方 0.02m、右侧 0.04m、高度 0m 处；
姿态上，相机绕 x 和 z 轴各旋转了 -90°（-π/2）  （轴是父坐标系gimbal_link）
，目的是把 OpenCV 相机坐标系（x 右 y 下 z 前）对齐到 ROS 标准坐标系（x 前 y 左 z 上）。


OpenCV 图像坐标系规则：
图像左上角是坐标原点 (0,0)
横轴 x：向右数值变大
纵轴 y：向下数值变大

模型输出单条数据格式（一行代表一个预测框）
[x1_off, y1_off, x2_off, y2_off, x3_off, y3_off, x4_off, y4_off, conf, 颜色得分..., 数字得分...]
前 8 个：4 个角点相对网格左上角的偏移量（不是像素坐标，是网格内偏移）
第 8 位索引：conf置信度，代表这里存在装甲的概率



1. OpenVINO 底层原始推理输出张量
ov::Tensor output_tensor
模型刚推理完，所有预测数据存在这里，是最原始的模型输出载体。
2. 转成 OpenCV 矩阵方便读取
cv::Mat output_buffer
把上面的张量映射成 Mat，代码里循环读取偏移、置信度都是操作这个变量。
3. 解码后所有候选装甲（未去重）
std::vector<Armor> candidates
遍历output_buffer解码每一行预测，生成的全部装甲候选都存在这里。
4. NMS 处理完、最终可用的装甲结果
std::vector<Armor> armors
去重 + 角点平滑后的最终模型识别输出，是detectWithModel函数返回给上层节点的结果。
一句话层级：
模型硬件输出 → output_tensor → 转可读矩阵 output_buffer → 解码候选 candidates → 筛选完成结果 armors
